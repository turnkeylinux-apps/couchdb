# CouchDB 19.0 test report

## Source decision

Debian Trixie does not provide a CouchDB package. CouchDB 19.0 therefore uses
the official Apache CouchDB APT repository for Trixie. The repository is
limited to the `couchdb` package by an origin preference and uses the existing
Apache package-signing key at `/usr/share/keyrings/couchdb.gpg`, fingerprint
`390E F70B B1EA 12B2 7739 6295 0EE6 2FB3 7A00 258D`.

The tested package and eligible update candidate are both
`3.5.2.1~trixie`. The non-destructive updater check refreshes APT metadata,
confirms the `trixie/main` Apache repository target and candidate, and verifies
that the installed package did not change.

## Acceptance command and evidence

Run from the integrated TurnKey harness checkout:

```sh
tools/test-v19-appliance couchdb --source /path/to/turnkey-apps/couchdb
```

The harness-generated `report.txt` is the authority for the accepted source
commit and archive, transported archive, input tree, build tree, harness tree,
and exact Docker invocation hashes. This avoids embedding a self-referential
source commit in this tracked report.

The functional implementation was exercised before this report in run
`20260824t041037z-3498-6246`, using source commit
`824f9f25bfb71fbd520103b482c6c5c419c3248c` and harness commit
`3c3216e54644a5e4627fb31a93470853816592aa`. That run passed the Trixie build,
configured-root import, normal init, firstboot, service, application, and APT
metadata refresh stages. It exposed a test-only APT 3 site-format expectation,
which was corrected before final acceptance. The final acceptance report is
retained by the harness under its CouchDB run directory.

The configured root uses the contract's narrow overlayfs fallback. The harness
first attempted `root.sandbox` and retained the Docker overlayfs `EINVAL`
mount trace before importing the otherwise complete `root.patched` result.

## Known limitations

Docker runtime validation does not exercise installer, kernel, hardware, or
ISO boot behavior. Those common paths are covered by the Core 19 baseline and
are not customized by this appliance.

## Deferred issues

- The build proxy CA is incompatible with CouchDB's bundled Erlang CA loader.
  Appliance configuration removes that temporary CA after the official APT
  package download and refreshes the bundle before CouchDB starts. Common
  final cleanup also removes temporary build trust. This affects only the
  Docker build environment and is not expected on an installed appliance.
- The CouchDB password inithook does not inspect the return status of each
  subprocess call. Normal firstboot administrator authentication passed end to
  end. A user is unlikely to encounter this unless a separate service or file
  failure occurs during firstboot, so it is deferred.
- Early harness attempts directly executed the test from a `noexec` `/run`
  mount and later lacked the local runtime network CA. Both test-environment
  main-flow blockers were corrected in the shared harness. They do not change
  appliance behavior.
- Dirty-source development mode records a cleanliness failure even when
  explicitly allowed. Acceptance uses a clean commit, so ordinary appliance
  users do not encounter this harness-only issue.
